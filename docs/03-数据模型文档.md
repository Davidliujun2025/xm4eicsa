# 智能对话工作台 — 数据模型文档

> **版本**：v1.0
> **日期**：2026-07-17
> **关联需求**：XM4-11
> **数据库**：MySQL 8.0+
> **时区**：所有 `DATETIME` 字段均为北京时间（UTC+8）

│    │ conversation_id   BIGINT    │──→ conversation.id（冗余，应用层引用）

### 关系说明

| 关系                              | 类型     | 说明                                              |
| --------------------------------- | -------- | ------------------------------------------------- |
| conversation → conversation_step | 1 : N    | 一次对话产生 1-5 条步骤记录（逐步生成，逐条插入） |
| conversation_step → favorite     | 1 : N    | 同一步骤可被多人收藏                              |
| favorite (user_id, step_id)       | 唯一约束 | 同一人对同一步骤只能收藏一次（点第二次是取消）    |

### 外键策略

**本模块所有表均不定义 FOREIGN KEY 约束**，理由：

| 关系                               | 不加外键的原因                                                                                                       |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| conversation_step → conversation  | conversation 计划使用软删除（迭代二），外键 CASCADE 物理删除会破坏软删除设计；应用层代码已控制插入顺序               |
| favorite → conversation_step      | 收藏采用内容快照（`content` 冗余存储），设计目标是与原始对话解耦——即使原对话被清理，收藏仍保留；外键会破坏此解耦 |
| favorite → user（鉴权系统用户表） | 用户表归属鉴权模块（其他同学维护），跨模块建外键是事故隐患                                                           |

引用完整性由应用层保证。

## 2. DDL（建表语句）

### 2.1 conversation（对话记录表）

```sql
CREATE TABLE conversation (
    id          BIGINT          NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    user_id     BIGINT          NOT NULL                 COMMENT '客服人员ID（关联鉴权系统用户表）',
    platform    VARCHAR(32)     NOT NULL                 COMMENT '服务平台：淘宝/天猫/京东/拼多多/抖音/小红书/快手/视频号/微信小店/其他平台',
    question    VARCHAR(500)    NOT NULL                 COMMENT '客户问题内容',
    category    VARCHAR(32)     DEFAULT NULL             COMMENT '问题分类：直接咨询/售后咨询/物流咨询/优惠活动咨询/发票咨询/适配性咨询/其他',
    status      VARCHAR(16)     NOT NULL DEFAULT 'generating' COMMENT '生成状态：generating/success/failed',
    created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最近更新时间',
    PRIMARY KEY (id),
    INDEX idx_user_id (user_id),
    INDEX idx_user_created (user_id, created_at DESC),
    INDEX idx_status (status),
    INDEX idx_category (category),
    CONSTRAINT chk_status CHECK (status IN ('generating', 'success', 'failed'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='对话记录表';
```

### 2.2 conversation_step（五步法步骤内容表）

```sql
CREATE TABLE conversation_step (
    id               BIGINT       NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    conversation_id  BIGINT       NOT NULL                 COMMENT '关联对话ID（应用层引用，无FK约束）',
    user_id          BIGINT       NOT NULL                 COMMENT '客服人员ID（冗余，方便按用户查询步骤）',
    step_order       TINYINT      NOT NULL                 COMMENT '步骤序号：1-意图识别 2-回复策略 3-推荐话术 4-钩子引导 5-成功收尾',
    step_type        VARCHAR(16)  NOT NULL                 COMMENT '步骤类型：意图识别/回复策略/推荐话术/钩子引导/成功收尾',
    title            VARCHAR(64)  DEFAULT NULL             COMMENT '步骤标题，如"第1步 - 意图识别"',
    label            VARCHAR(32)  DEFAULT NULL             COMMENT '内容标签，如"客户意图"（所有步骤均可编辑）',
    tags             JSON         DEFAULT NULL             COMMENT '标签数组，如["退换货咨询", "理性询问"]（所有步骤均可编辑）',
    section          VARCHAR(32)  DEFAULT NULL             COMMENT '内容区块名，如"关键词"',
    body             TEXT         NOT NULL                 COMMENT '步骤核心内容（所有步骤均可编辑）',
    risk_warning     JSON         DEFAULT NULL             COMMENT '平台风险提示（仅第3步推荐话术有值）{"hasRisk":bool,"description":"...","alternative":"..."}',
    status           VARCHAR(64)  DEFAULT NULL             COMMENT '步骤状态展示文本（如"已识别淘宝客户问题类型与核心诉求"，非机器状态码）',
    created_at       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（AI生成完成时间）',
    updated_at       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最近编辑时间',
    PRIMARY KEY (id),
    INDEX idx_conversation (conversation_id),
    INDEX idx_conv_step (conversation_id, step_order),
    INDEX idx_step_user (user_id),
    CONSTRAINT chk_step_order CHECK (step_order BETWEEN 1 AND 5)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='AI生成五步法步骤内容表';
```

### 2.3 favorite（话术收藏表）

```sql
CREATE TABLE favorite (
    id               BIGINT       NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    user_id          BIGINT       NOT NULL                 COMMENT '客服人员ID',
    conversation_id  BIGINT       DEFAULT NULL             COMMENT '关联对话ID（冗余字段，方便查询）',
    step_id          BIGINT       NOT NULL                 COMMENT '关联步骤ID，对应conversation_step.id',
    step_type        VARCHAR(16)  NOT NULL                 COMMENT '步骤类型：意图识别/回复策略/推荐话术/钩子引导/成功收尾',
    content          TEXT         NOT NULL                 COMMENT '话术内容快照（收藏时原样保存）',
    platform         VARCHAR(32)  NOT NULL                 COMMENT '服务平台',
    category         VARCHAR(32)  DEFAULT NULL             COMMENT '问题分类（快照，如退换货咨询）',
    question         VARCHAR(500) DEFAULT NULL             COMMENT '关联的客户问题',
    collected_at     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '收藏时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_user_step (user_id, step_id),
    INDEX idx_user (user_id),
    INDEX idx_user_collected (user_id, collected_at DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='话术收藏表';
```

## 3. 字段详解

### 3.1 conversation 表

| 字段           | 类型     | 长度 | 必填 | 默认值         | 说明                                                                    |
| -------------- | -------- | ---- | ---- | -------------- | ----------------------------------------------------------------------- |
| `id`         | BIGINT   | —   | 是   | 自增           | 主键                                                                    |
| `user_id`    | BIGINT   | —   | 是   | —             | 客服人员 ID。来自鉴权系统用户表，**本模块不维护用户表，只存引用** |
| `platform`   | VARCHAR  | 32   | 是   | —             | 10 个可选值之一                                                         |
| `question`   | VARCHAR  | 500  | 是   | —             | 与前端 textarea maxLength=500 对齐                                      |
| `category`   | VARCHAR  | 32   | 否   | NULL           | AI 生成后回填。可选值见下方枚举表                                       |
| `status`     | VARCHAR  | 16   | 是   | `generating` | 三态：`generating` → `success` / `failed`                        |
| `created_at` | DATETIME | —   | 是   | 当前时间       | 对话创建时间（北京时间）                                                |
| `updated_at` | DATETIME | —   | 是   | 当前时间       | 自动更新，每次编辑步骤保存时刷新                                        |

**category 枚举值**（由 AI 分类结果决定）：

| 值               | 含义               |
| ---------------- | ------------------ |
| `直接咨询`     | 客户直接问产品信息 |
| `售后咨询`     | 退货/退款/换货相关 |
| `物流咨询`     | 发货/快递/到货相关 |
| `优惠活动咨询` | 优惠券/活动/折扣   |
| `发票咨询`     | 开票/发票类型      |
| `适配性咨询`   | 兼容性/型号匹配    |
| `其他`         | 无法归入以上分类   |

**status 状态流转**：

```
generating ──→ success
     │
     └──────→ failed
```

- 创建对话时先插入 `generating` 状态
- 第 5 步生成成功后更新为 `success`
- 单步 AI 调用失败时**保持 `generating` 状态**，用户可重试当前步骤（`failed` 状态预留用于对话级不可恢复错误，如 Token 耗尽）

### 3.2 conversation_step 表

| 字段                | 类型        | 必填 | 说明                                                                                                          |
| ------------------- | ----------- | ---- | ------------------------------------------------------------------------------------------------------------- |
| `id`              | BIGINT      | 是   | 主键，收藏时用作`step_id` 引用                                                                              |
| `conversation_id` | BIGINT      | 是   | 关联 conversation.id（应用层引用，无 FK 约束）                                                                |
| `user_id`         | BIGINT      | 是   | 客服人员 ID（冗余，方便按用户维度查询步骤）                                                                   |
| `step_order`      | TINYINT     | 是   | 1-5，固定顺序，CHECK 约束 (1-5)                                                                               |
| `step_type`       | VARCHAR(16) | 是   | `意图识别` / `回复策略` / `推荐话术` / `钩子引导` / `成功收尾`                                      |
| `title`           | VARCHAR(64) | 否   | 展示标题，如`"第1步 - 意图识别"`                                                                            |
| `label`           | VARCHAR(32) | 否   | 内容类别标签（**所有步骤均可编辑**）                                                                    |
| `tags`            | JSON        | 否   | 标签数组（**所有步骤均可编辑**）。MySQL JSON 类型，存储如 `["退换货咨询", "理性询问"]`                |
| `section`         | VARCHAR(32) | 否   | 内容区块标题，如`"关键词"`                                                                                  |
| `body`            | TEXT        | 是   | 步骤核心内容（**所有步骤均可编辑**）。TEXT 最大 64KB，满足话术内容长度需求                              |
| `risk_warning`    | JSON        | 否   | **仅 step_order=3（推荐话术）有值**，其余步骤为 NULL                                                    |
| `status`          | VARCHAR(64) | 否   | **展示字段**，步骤状态的自然语言描述（如 `"已识别淘宝客户问题类型与核心诉求"`），不作为状态机判断依据 |
| `created_at`      | DATETIME    | 是   | 创建时间（≈ AI 生成完成时间，北京时间）                                                                      |
| `updated_at`      | DATETIME    | 是   | 最近编辑时间，每次客服通过 PUT 接口修改该步骤时自动更新                                                       |

**步骤可编辑字段说明**：

| 可编辑字段               | 不可编辑字段               |
| ------------------------ | -------------------------- |
| `body` — 核心内容文本 | `step_order` — 步骤序号 |
| `label` — 内容标签    | `step_type` — 步骤类型  |
| `tags` — 标签数组     | `title` — 步骤标题      |
|                          | `section` — 内容区块名  |

- 所有五步（step_order 1-5）的 `body`、`label`、`tags` 均可编辑，不区分步骤类型
- 前端通过 `PUT /api/v1/conversations/{id}` 一次性提交所有已生成步骤（1-5 条，取决于当前进度）
- 后端只更新三个可编辑字段，结构性字段传入的值会被忽略
- `updated_at` 在每次 PUT 保存时自动更新（MySQL `ON UPDATE CURRENT_TIMESTAMP`）
- 步骤编辑时，`conversation.updated_at` 也同步刷新（应用层在 PUT 逻辑中显式更新）
- `editable` 为 API 响应中的**计算字段**（非数据库列），始终返回 `true`

**risk_warning JSON 结构**：

```json
// 无风险时
{
  "hasRisk": false,
  "description": null,
  "alternative": null
}

// 有平台表达风险时（如小红书）
{
  "hasRisk": true,
  "description": "话术中存在可能不适合该平台的营销表达",
  "alternative": "建议改为更中性的描述，以商品页与平台规则为准"
}
```

### 3.3 favorite 表

| 字段                | 类型         | 必填 | 说明                                                                                     |
| ------------------- | ------------ | ---- | ---------------------------------------------------------------------------------------- |
| `id`              | BIGINT       | 是   | 主键                                                                                     |
| `user_id`         | BIGINT       | 是   | 收藏人 ID                                                                                |
| `conversation_id` | BIGINT       | 否   | 冗余字段，方便查询"某次对话的收藏"，不做外键约束                                         |
| `step_id`         | BIGINT       | 是   | 关联 conversation_step.id，唯一约束`uk_user_step (user_id, step_id)` 防重复收藏        |
| `step_type`       | VARCHAR(16)  | 是   | 冗余字段，避免每次查收藏列表都要 JOIN step 表                                            |
| `content`         | TEXT         | 是   | 话术内容快照。收藏时直接复制，**不依赖原 step 记录**（即使原对话删除，收藏仍保留） |
| `platform`        | VARCHAR(32)  | 是   | 服务平台                                                                                 |
| `category`        | VARCHAR(32)  | 否   | 问题分类（快照），与 conversation.category 统一命名                                      |
| `question`        | VARCHAR(500) | 否   | 关联的客户问题                                                                           |
| `collected_at`    | DATETIME     | 是   | 收藏时间（北京时间）                                                                     |

**为什么 content、platform、step_type 要做冗余存储？**

话术库是独立的能力（对应 XM4-12 用户故事）。如果对话记录被清理，收藏的内容不应丢失。因此收藏时做"快照"，把内容完整复制过来，与原对话解耦。

## 4. JSON 字段 Schema

### 4.1 tags 字段（conversation_step 表）

```json
{
  "type": "array",
  "items": { "type": "string", "maxLength": 32 },
  "minItems": 0,
  "maxItems": 10,
  "description": "标签数组，如 [\"退换货咨询\", \"理性询问\"]"
}
```

### 4.2 risk_warning 字段（conversation_step 表）

```json
{
  "type": "object",
  "properties": {
    "hasRisk": { "type": "boolean" },
    "description": { "type": "string", "nullable": true },
    "alternative": { "type": "string", "nullable": true }
  },
  "required": ["hasRisk"]
}
```

> 应用层在写入和读取时需校验上述 JSON Schema。MySQL JSON 类型只做语法校验（能解析为 JSON 即接受），不做 Schema 级验证。

## 5. 索引设计

| 表                | 索引名                 | 索引字段                          | 类型               | 理由                                   |
| ----------------- | ---------------------- | --------------------------------- | ------------------ | -------------------------------------- |
| conversation      | `idx_user_id`        | `user_id`                       | 普通索引           | 按客服人员查询对话                     |
| conversation      | `idx_user_created`   | `(user_id, created_at DESC)`    | 联合索引           | 对话列表页按时间倒序分页查询（最频繁） |
| conversation      | `idx_status`         | `status`                        | 普通索引           | 查询生成中的对话                       |
| conversation      | `idx_category`       | `category`                      | 普通索引           | 对话列表按分类筛选                     |
| conversation_step | `idx_conversation`   | `conversation_id`               | 普通索引           | 通过对话 ID 关联查询所有步骤           |
| conversation_step | `idx_conv_step`      | `(conversation_id, step_order)` | 联合索引           | 按对话 + 步骤顺序查询（最常用）        |
| conversation_step | `idx_step_user`      | `user_id`                       | 普通索引           | 按用户维度查询步骤（如统计报表）       |
| favorite          | `uk_user_step`       | `(user_id, step_id)`            | **唯一索引** | 确保同一人不对同一步骤重复收藏         |
| favorite          | `idx_user`           | `user_id`                       | 普通索引           | 按用户查所有收藏                       |
| favorite          | `idx_user_collected` | `(user_id, collected_at DESC)`  | 联合索引           | 话术库列表分页查询                     |

## 6. 时区约定

**所有 `DATETIME` 字段均表示北京时间（UTC+8）**。服务器、数据库连接、前端展示均需统一使用北京时间。若未来跨时区部署，迁移至 `TIMESTAMP` 类型或通过应用层统一转换处理。

MySQL 连接配置需添加：

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/carepilot?serverTimezone=Asia/Shanghai
```

## 8. 数据清理策略（留待后续迭代）

| 场景         | 建议策略                                               | 状态         |
| ------------ | ------------------------------------------------------ | ------------ |
| 对话记录删除 | 软删除（`is_deleted` 字段或 `status = 'deleted'`） | 待迭代二实现 |
| 步骤内容清理 | 随对话软删除                                           | 同上         |
| 收藏清理     | 用户主动取消收藏（物理删除）                           | 已实现       |
| 历史数据归档 | T+N 月归档到备份表                                     | 待讨论       |
