# 找回密码流程说明

## 1. 功能目标

当客服忘记登录密码时，可以在无人值守的情况下通过绑定手机号和短信验证码完成密码重置，重置成功后使用新密码返回登录页正常登录系统。

## 2. 参与角色

| 角色 | 说明 |
| --- | --- |
| 客服用户 | 忘记登录密码，需要自助重置。 |
| 前端页面 | 展示重置页面、输入框、按钮、倒计时和错误提示。 |
| 后端服务 | 校验账号、发送验证码、校验验证码、更新密码。 |
| MySQL 数据库 | 保存客服账号、重置凭证、短信验证码记录。 |
| 短信服务 | 向绑定手机号发送 6 位数字验证码。 |

## 3. 主流程

```text
1. 用户打开登录页。
2. 用户输入账号，点击“忘记密码”。
3. 前端调用账号校验接口。
4. 后端校验账号格式、账号是否存在、账号是否可用。
5. 校验通过后，后端生成 resetToken，并返回脱敏手机号。
6. 前端进入密码重置页面。
7. 用户输入绑定手机号，点击“获取验证码”。
8. 后端校验 resetToken 是否有效、手机号是否属于当前账号。
9. 校验通过后，后端生成 6 位短信验证码，保存验证码哈希，并调用短信服务发送验证码。
10. 前端按钮进入 60 秒倒计时，倒计时期间不可重复点击。
11. 用户输入短信验证码、新密码、确认新密码，点击“提交重置”。
12. 后端校验验证码是否正确且未过期，校验新密码规则。
13. 后端使用 BCrypt 生成新密码哈希，更新 customer_service_user.password_hash。
14. 后端将 resetToken 和验证码标记为已使用。
15. 前端弹窗提示“密码重置成功”，并提供返回登录页入口。
16. 用户使用新密码回到登录页，可正常登录系统。
```

## 4. 页面输入项

重置页面包含 4 个输入项：

| 输入项 | 校验要求 |
| --- | --- |
| 绑定手机号 | 必填，11 位手机号格式，且必须绑定当前客服账号。 |
| 短信验证码 | 必填，6 位数字，且必须与后端最近一次有效验证码一致。 |
| 新密码 | 必填，12-20 位，至少包含大写、小写、数字、特殊符号中的三类。 |
| 确认新密码 | 必填，必须与新密码一致。 |

页面按钮：

| 按钮 | 行为 |
| --- | --- |
| 获取验证码 | 校验手机号后发送短信验证码，成功后进入 60 秒倒计时。 |
| 提交重置 | 校验验证码和新密码，成功后更新密码并提示完成。 |
| 返回登录 | 重置成功后返回登录页。 |

## 5. 异常流程

| 场景 | 前端提示 | 后端错误码 |
| --- | --- | --- |
| 用户名格式不正确 | 用户不存在或用户名格式不正确 | `USERNAME_INVALID` |
| 用户名不存在 | 用户不存在 | `USER_NOT_FOUND` |
| 手机号未输入 | 请输入绑定手机号 | `PHONE_REQUIRED` |
| 手机号未绑定任何客服账号 | 该手机号未绑定任何客服账号 | `PHONE_NOT_BOUND` |
| 手机号不是当前账号绑定手机号 | 该手机号未绑定当前账号 | `PHONE_NOT_MATCH` |
| 60 秒内重复获取验证码 | 验证码已发送，请稍后再试 | `SMS_CODE_COOLDOWN` |
| 验证码为空 | 请输入短信验证码 | `SMS_CODE_EMPTY` |
| 验证码错误或过期 | 验证码为空或错误 | `SMS_CODE_INVALID` |
| 两次新密码不一致 | 两次输入的新密码不一致 | `PASSWORD_NOT_MATCH` |
| 新密码不符合规则 | 密码需为 12-20 位，且至少包含三类字符 | `PASSWORD_INVALID` |
| 账号被禁用 | 账号已禁用，请联系管理员 | `ACCOUNT_DISABLED` |

## 6. 状态流转

```text
INIT
  ↓ 账号校验成功
ACCOUNT_VERIFIED
  ↓ 验证码发送成功
CODE_SENT
  ↓ 验证码和新密码校验成功
RESET_DONE
```

异常状态：

```text
TOKEN_EXPIRED：resetToken 过期，需要重新验证账号。
CODE_EXPIRED：短信验证码过期，需要重新获取验证码。
RESET_FAILED：验证码或密码校验失败，停留在当前页面并展示错误提示。
```

## 7. 验收标准对应关系

| 验收点 | 实现说明 |
| --- | --- |
| 只有格式正确且真实存在的用户名可进入重置页 | 登录页或重置页先调用账号校验接口。 |
| 重置页包含 4 个输入项和 2 个按钮 | 页面展示绑定手机号、验证码、新密码、确认新密码，以及获取验证码、提交重置按钮。 |
| 手机号为空时提示 | 前端必填校验，后端返回 `PHONE_REQUIRED`。 |
| 手机号未绑定账号时提示 | 后端查询账号表，返回 `PHONE_NOT_BOUND`。 |
| 已绑定手机号可收到 6 位验证码 | 后端生成 6 位验证码并调用短信服务。 |
| 获取验证码按钮 60 秒不可重复点击 | 后端返回 `cooldownSeconds=60`，前端倒计时。 |
| 验证码错误或密码不合规无法重置 | 后端统一校验验证码和密码规则。 |
| 信息全部正确后重置成功 | 后端更新密码哈希并返回 `BACK_TO_LOGIN`。 |
| 新密码可正常登录 | 登录模块使用同一张用户表和同一种 BCrypt 密码哈希。 |
| 页面品牌统一 | 前端沿用登录页的 CarePilot AI 标识、配色和布局风格。 |

## 8. 后续联调注意事项

- 登录模块当前账号字段是 `customer_service_user.account`，并且账号本身就是手机号。
- 找回密码后端需要复用登录模块中的密码加密方式，避免新密码写入后登录模块无法校验。
- 如果短信服务暂时不可用，可以先使用控制台打印验证码或测试短信服务，接口结构保持不变。
- 最终部署时需要把找回密码接口加入网关或 Nginx 路由，路径为 `/api/password/**`。
- 如果前端使用独立 Vite 项目，最终应与登录页面入口 `forgot-password.html` 对齐。
