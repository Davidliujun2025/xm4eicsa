## 5. 核心流程

### 5.1 逐步生成五步法回复（串行模式）

五步法采用**逐步串行生成**：客服触发创建对话 → 后端生成第 1 步（意图识别）→ 客服可编辑 → 点击"下一步"触发第 2 步生成 → 第 2 步 Prompt 注入客服编辑后的第 1 步 body → 以此类推，直至第 5 步完成。

**首次创建对话并生成第 1 步**：

```
POST /api/v1/conversations

客服人员          前端              Controller              Service            QwenClient
  │               │                    │                      │                   │
  │ 输入问题+平台  │                    │                      │                   │
  │──────────────>│                    │                      │                   │
  │               │ POST /conversations│                      │                   │
  │               │───────────────────>│                      │                   │
  │               │                    │ 1. 参数校验           │                   │
  │               │                    │ 2. AuthContext.getUserId()               │
  │               │                    │ 3. 插入 conversation   │                   │
  │               │                    │    (status=generating) │                   │
  │               │                    │ 4. PromptBuilder.     │                   │
  │               │                    │    buildStep1Prompt() │                   │
  │               │                    │ 5. qwenClient.call()  │                   │
  │               │                    │──────────────────────>│                   │
  │               │                    │                       │ 返回占位文本       │
  │               │                    │<──────────────────────│ (框架阶段)         │
  │               │                    │ 6. 保存 conversation_ │                   │
  │               │                    │    step (step_order=1)│                   │
  │               │                    │ 7. 组装响应           │                   │
  │               │  返回 conversation  │                      │                   │
  │               │  + steps[step1]    │                      │                   │
  │               │<───────────────────│                      │                   │
  │               │                    │                      │                   │
  │ 查看/编辑step1 │                    │                      │                   │
```

**逐步生成后续步骤**：

```
POST /api/v1/conversations/{id}/generate-next

客服人员          前端              Controller              Service            QwenClient
  │               │                    │                      │                   │
  │ 编辑step1后   │                    │                      │                   │
  │ 点击"下一步"   │                    │                      │                   │
  │──────────────>│                    │                      │                   │
  │               │ POST /conversations│                      │                   │
  │               │ /{id}/generate-next│                      │                   │
  │               │───────────────────>│                      │                   │
  │               │                    │ 1. 校验对话状态       │                   │
  │               │                    │    (必须为generating) │                   │
  │               │                    │ 2. 读取已有 steps     │                   │
  │               │                    │    (取 DB 最新 body,  │                   │
  │               │                    │     即用户编辑后的)    │                   │
  │               │                    │ 3. PromptBuilder.     │                   │
  │               │                    │    buildStepNPrompt() │                   │
  │               │                    │    (注入前序step body) │                   │
  │               │                    │ 4. qwenClient.call()  │                   │
  │               │                    │──────────────────────>│                   │
  │               │                    │<──────────────────────│                   │
  │               │                    │ 5. 插入 conversation_ │                   │
  │               │                    │    step (step_order=N)│                   │
  │               │                    │ 6. 若 N=5:           │                   │
  │               │                    │    status = success   │                   │
  │               │  返回 stepN        │                      │                   │
  │               │<───────────────────│                      │                   │
  │               │                    │                      │                   │
  │ 查看/编辑stepN │                    │                      │                   │
  │ 可继续触发     │                    │                      │                   │
  │ generate-next  │                    │                      │                   │
```

**串行依赖关系**：

```
POST /conversations
  → 生成 step1 (意图识别)
       │  用户编辑 step1 的 body
       │  点击"下一步"
       ▼
POST /conversations/{id}/generate-next
  → Prompt 注入 step1 当前 body → 生成 step2 (回复策略)
       │  用户编辑 step2 的 body
       │  点击"下一步"
       ▼
POST /conversations/{id}/generate-next
  → Prompt 注入 step1+step2 当前 body → 生成 step3 (推荐话术)
       │  用户编辑 step3 的 body
       │  点击"下一步"
       ▼
POST /conversations/{id}/generate-next
  → Prompt 注入 step1-3 当前 body → 生成 step4 (钩子引导)
       │  用户编辑 step4 的 body
       │  点击"下一步"
       ▼
POST /conversations/{id}/generate-next
  → Prompt 注入 step1-4 当前 body → 生成 step5 (成功收尾)
  → conversation.status = success
```

### 5.2 编辑五步法内容（静默保存）

```
PUT /api/v1/conversations/{id}

客服人员                  前端                         Controller / Service
  │                        │                              │
  │ 在任意步骤中修改文字     │                              │
  │───────────────────────>│                              │
  │                        │ 停止输入 1s 后 / 失焦时       │
  │                        │ 组装所有已生成步骤的最新文本    │
  │                        │                              │
  │                        │ PUT /conversations/{id}      │
  │                        │ 请求体: { steps: [...] }     │
  │                        │─────────────────────────────>│
  │                        │                              │ 1. 校验对话存在
  │                        │                              │ 2. 逐条更新 step 的
  │                        │                              │    body / label / tags
  │                        │                              │    （仅此三个字段）
  │                        │                              │ 3. 忽略 step_type /
  │                        │                              │    title / section 等
  │                        │                              │    结构性字段的变更
  │                        │                              │
  │                        │  200 OK（无弹窗提示）         │
  │                        │<─────────────────────────────│
  │                        │                              │
  │ 继续编辑，不受影响      │                              │
```

**关键规则**：

- 前端防抖：停止输入 1 秒后触发保存，或输入框失去焦点时触发
- 每次保存提交**所有已生成步骤的完整最新文本**（1-5 条，取决于当前生成进度）
- 保存全程静默，不弹「保存成功」提示
- 所有五步（step_order 1-5）均可编辑，无例外
- 本次迭代中，编辑某一步**不影响**其他步骤——没有级联变灰、没有级联重新生成
- 后端只更新 `body`、`label`、`tags` 三个可编辑字段；`step_type`、`step_order`、`title`、`section` 等结构性字段不接受修改
- 步骤编辑保存时，`conversation.updated_at` 同步刷新（应用层显式更新），确保列表页的"最近更新时间"准确

> **注意**：若用户在触发 `generate-next` 前未通过 PUT 保存编辑，`generate-next` 读取的是数据库中的当前版本（上次 PUT 保存的内容或 AI 原始输出）。前端应在用户点击"下一步"前确保最新编辑已通过 PUT 落库。

## 6. AI 模块对接设计

### 6.1 QwenClient 接口

```java
package com.carepilot.infra.ai;

/**
 * AI 调用客户端。
 * 框架阶段返回占位文本；AI 同学后续替换为真实 DashScope HTTP 调用。
 */
public interface QwenClient {
    /**
     * 调用通义千问生成单步结果。
     *
     * @param prompt 完整的 Prompt 字符串（由 PromptBuilder 组装）
     * @return AI 返回的原始 JSON 字符串
     * @throws AiGenerationException 调用失败或超时时抛出
     */
    String call(String prompt) throws AiGenerationException;
}
```

**框架阶段默认实现**：

```java
// 占位实现，后续替换
@Component
public class StubQwenClient implements QwenClient {
    @Override
    public String call(String prompt) {
        return "{ \"body\": \"[AI 生成中...]\", \"label\": \"待生成\", \"tags\": [] }";
    }
}
```

AI 同学接入时创建 `DashScopeQwenClient implements QwenClient`，替换 Spring Bean 即可。Controller 和 Service 层代码**不需要任何修改**。

### 6.2 PromptBuilder 职责

`PromptBuilder` 负责根据当前步骤序号和已有上下文动态组装 Prompt 字符串：

```
Step1 Prompt = 系统指令 + 平台信息 + 客户问题

Step2 Prompt = 系统指令 + 平台信息 + 客户问题 + Step1 当前 body

Step3 Prompt = 系统指令 + 平台信息 + 客户问题
             + Step1 当前 body + Step2 当前 body
             + 风险检测指令（仅此步）

Step4 Prompt = 系统指令 + 平台信息 + 客户问题
             + Step1-3 当前 body

Step5 Prompt = 系统指令 + 平台信息 + 客户问题
             + Step1-4 当前 body
```

> **关键**：每步 Prompt 注入的是**数据库中最新的 step body**——即用户可能已编辑保存后的内容，而不是 AI 原始输出。这确保客服修正 AI 的识别偏差后，后续步骤基于正确的上下文生成。

## 7. 关键设计决策

| 决策点       | 方案                                                                                      | 理由                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 生成策略     | **逐步串行生成**：POST /conversations 仅生成第 1 步；generate-next 逐步生成后续步骤 | 客服可修正每步 AI 输出后再触发下一步；每步独立请求、失败影响范围小                      |
| 步骤创建方式 | **随生成逐条插入**，不预创建空步骤                                                  | `steps.length` 即生成进度，前端无需额外判断；与逐步生成语义一致                       |
| 可编辑范围   | **全部五步可编辑**（body / label / tags）                                           | 每一步的 AI 输出都可能需要人工修正，不做区分                                            |
| AI 对接方式  | QwenClient 接口 + 框架阶段占位实现                                                        | AI 接入时只替换 Bean 实现，Controller/Service 零改动                                    |
| 编辑保存策略 | 前端防抖 1s / 失焦触发 → PUT 一次性提交所有已生成步骤                                    | 静默保存，不弹提示；一次性提交避免多次请求                                              |
| 超时处理     | 单步请求**15s 超时**（响应时间目标 ≤5s）                                         | 单次 Qwen 调用通常 1-3s，15s 为硬截止时间；5s 为正常体验目标（AC23）                   |
| 失败处理     | 单步失败直接返回错误，conversation**保持 generating 状态**，用户手动重试；不做后端自动重试 | 保持 generating 允许用户重试当前步骤；failed 状态预留用于对话级不可恢复错误（如 Token 耗尽） |
| 级联重新生成 | **本迭代不做**                                                                      | 编辑后各步骤独立，互不影响；级联逻辑留待后续迭代                                        |
| 平台列表     | 后端硬编码常量，不存数据库                                                                | 10 个平台固定不变，查数据库增加无谓 IO                                                  |
| 外键策略     | **所有表不加 FOREIGN KEY**                                                          | conversation 计划软删除，外键 CASCADE 会冲突；favorite 快照解耦；用户表跨模块不可建外键 |
| AuthContext  | 框架阶段`getUserId()` 返回 Mock=1                                                       | 鉴权就绪后一行代码切换                                                                  |
| Token 接口   | 框架阶段返回 Mock 固定值                                                                  | 不阻塞开发，Token 同学就绪后切换数据源                                                  |

## 8. 非功能需求

| 类别         | 要求                             | 实现方式                                        |
| ------------ | -------------------------------- | ----------------------------------------------- |
| 响应时间     | 单步生成 ≤5s（框架阶段 <100ms） | 框架阶段无网络 IO，仅 DB 操作                   |
| 并发         | 支持 50-100 客服同时在线         | Spring Boot 内置 Tomcat 线程池（默认 200 线程） |
| 数据库连接池 | 峰值 30 并发连接                 | HikariCP`maximum-pool-size=30`                |
| 异常处理     | 所有异常统一 JSON 返回           | GlobalExceptionHandler                          |
| 日志         | 关键操作有日志                   | SLF4J + Logback（Spring Boot 默认）             |
| 参数校验     | 前端 + 后端双重校验              | Jakarta Validation 注解                         |
| CORS         | 允许前端跨域访问                 | WebConfig 配置                                  |

### 8.1 并发分析

逐步生成模式下，每次 `generate-next` 为 1 次独立请求：

```
N 个客服同时触发 generate-next
  → N 个 HTTP 请求到达 Spring Boot
    → Tomcat 线程池（默认 200 线程）
      → 每个线程：校验 + DB 读写 + 1 次 AI 调用（框架阶段跳过）
        → HikariCP 连接池
```

| 节点            | 默认值 | 评估                  | 建议              |
| --------------- | ------ | --------------------- | ----------------- |
| Tomcat 线程池   | 200    | 30 并发绰绰有余       | 保持默认          |
| HikariCP 连接池 | 10     | 30 并发至少 30 个连接 | **调至 30** |

```properties
spring.datasource.hikari.maximum-pool-size=30
spring.datasource.hikari.minimum-idle=5
```

## 10. 风险与缓解

| 风险                 | 影响                              | 缓解措施                                                                   |
| -------------------- | --------------------------------- | -------------------------------------------------------------------------- |
| AI 模块接口不匹配    | 对接时需要改动 Controller/Service | QwenClient 接口先行定义好，AI 同学按接口实现                               |
| 鉴权接口未就绪       | 无法获取真实用户 ID               | AuthContext Mock userId=1，后续一键切换                                    |
| Token 消耗表未建好   | 查询报错                          | Token 接口先返回 Mock 数据                                                 |
| 收藏模块依赖 step.id | 若 step 被删除则收藏失效          | 收藏采用内容快照存储，与原 step 解耦                                       |
| Qwen API 不稳定      | 单步生成失败                      | 已生成步骤持久化保留；失败时 conversation 保持 generating 状态，用户可重试 |
| 逐步生成交互次数多   | 客服觉得操作繁琐                  | 每步生成 ~1-3s（AI 接入后），交互自然；框架阶段响应更快                    |
